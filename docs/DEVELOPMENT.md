# HandsFree

Developer reference. For the prebuilt beta, see [the main README](../README.md). Commands below run from the repository root. See also [release packaging](RELEASING.md).

A native macOS menu-bar dictation app for Apple Silicon (macOS 14+). Tap **Fn / 🌐** to record, tap again to transcribe locally and paste into the original text field. **Escape** cancels. The compact **150 × 44 pt** bottom-center capsule is an AppKit **non-activating NSPanel**, not a web window; it does not take keyboard focus. While recording, its circular **×** cancels, its blue **✓** finishes, and its lime bars respond to actual microphone power. Processing shrinks over 220 ms to a text-free **54 × 28 pt** capsule with three softly breathing lime dots; Reduce Motion skips the shrink and keeps the dots static. The transparent backing panel remains fixed to avoid clipping and passes clicks through during processing. Escape and the dashboard's Cancel still work, and the native accessibility label is “Transcribing.” Silence shows **“No speech”** briefly on a single centered line, while detailed errors remain in the dashboard.

## Build and launch

Requires Apple Silicon, Node **22.18+** (24 recommended), Rust stable, CMake, and current Xcode Command Line Tools with Swift and a macOS SDK. No Python runtime, account, paid API, or cloud transcription service is needed. Full Xcode may be needed if your Command Line Tools lack the Metal toolchain.

```sh
# From your checkout of this repository:
npm ci
npm run tauri build -- --bundles app
open src-tauri/target/release/bundle/macos/HandsFree.app
```

The default build is ad-hoc-signed for local use, not notarized distribution. Nothing installs into `/Applications` automatically. Launch the **same app bundle from the same path** after granting permissions; rebuilding/moving ad-hoc-signed binaries can invalidate macOS permission grants. Use the opt-in local signing workflow below for repeatable identity across rebuilds.

For normal use, quit the app, copy `src-tauri/target/release/bundle/macos/HandsFree.app` into `/Applications`, and launch that copy **before granting permissions**. If HandsFree is missing from Accessibility or Input Monitoring, click **+** in that pane and choose `/Applications/HandsFree.app`, then enable its switch. Quit and reopen HandsFree after granting access. The bundle identifier remains **`com.handsfree.local`** so the branding change does not intentionally migrate permissions or local data; rebuilding ad-hoc signatures may still require reauthorization. Avoid keeping multiple app copies running.

For frontend/native development: `npm run tauri dev`. Use the bundled `.app` for reliable privacy permission attribution; dev runs may show the terminal or development binary in System Settings. `npm run dev` alone only serves the settings UI and has no native bridge.

### Read-only startup diagnostics

`~/Library/Application Support/com.handsfree.local/diagnostics.json` is written atomically with owner-only access at startup, on status queries, and every two seconds even with the window hidden. It reports the running PID/executable/hash, actual in-process permission bits (1 microphone, 2 Accessibility, 4 Input Monitoring), microphone authorization status (0 undetermined, 1 restricted, 2 denied, 3 authorized), Fn connection/reason, verified model readiness and file size, phase, and message. It contains no audio, transcript, focus details, or usage history. Check its PID and timestamp rather than assuming a file from an exited process is current. Reading it needs no IPC, browser, microphone capture, or permission prompt.

If enabled privacy switches disagree with this running app's diagnostics after rebuilding, an old ad-hoc identity may be authorized instead. A rebuild changes its CDHash-based designated requirement. Do not redownload a verified model or reset all TCC grants. Quit HandsFree, remove/re-add **this installed copy** in Accessibility and Input Monitoring, and reopen it; microphone recovery depends on the reported authorization state. A microphone status of `0` means not yet determined for this identity, not a denied grant. Diagnostics establish the current process's access, not which older identity a Settings row authorized.

### Stable local signing (explicit opt-in, macOS)

```sh
npm run signing:init   # one time, only when you want a dedicated local identity
npm run build:local    # subsequent builds: bundle, sign, verify
# Quit HandsFree before replacing /Applications/HandsFree.app, then reopen it.
```

`signing:init` creates a dedicated self-signed RSA certificate with **CA:false**, digital-signature key usage and **codeSigning-only** EKU, and imports its private key into your existing login keychain with `/usr/bin/codesign` as the allowed application. It does **not** mark the certificate trusted, modify the keychain search list, grant other apps key access, or touch privacy settings/TCC. macOS may ask you to unlock/approve access to the login keychain; this script never supplies your login password or disables keychain protection. The temporary encrypted private key, PKCS#12 and random passphrase are owner-only and removed on exit; only the public certificate remains in `~/Library/Application Support/HandsFree Local Signing/`. No secrets belong in the repository.

`build:local` keeps the bundle identifier `com.handsfree.local` and explicitly pins the designated requirement to **both that identifier and the dedicated certificate's SHA-1 fingerprint** (the fingerprint is an identity locator, not the signature algorithm). It verifies the final signature and pinned requirement. SHA-256 signs the certificate. No identifier-only requirement or broad trust is used. `security find-identity -v` can still report zero *trusted* identities: this untrusted self-signed certificate can sign and satisfy its explicit pinned requirement without becoming a trusted certificate authority. This is local signing, not Apple Developer ID/notarization or Gatekeeper distribution approval. If signing fails on your machine, stop and inspect the error; do not change global trust to make it work.

The certificate must be kept for future rebuilds; re-running initialization refuses to replace it. Deleting its private key or replacing the certificate creates a different app identity and requires reauthorization. Ordinary `npm run tauri build` remains ad-hoc; use **`npm run build:local`** for the final installable local bundle. The helper can also explicitly sign an existing build with `bash scripts/local-signing.sh --sign /path/to/HandsFree.app`; it refuses unrelated bundle identifiers. It does not install or launch anything automatically.

**One-time migration:** switching from an ad-hoc signature does not inherit prior privacy grants. Install the final signed copy at `/Applications/HandsFree.app`, reopen it, and authorize that exact copy yourself in Accessibility and Input Monitoring. Grant microphone access from the app only when ready to test recording. No signing workflow can grant these permissions on your behalf. Future builds signed with this same identity keep the same designated requirement, though macOS ultimately controls authorization.

## First run (explicit actions only)

1. Open **Settings** in the dashboard. Click **Allow** for Microphone. If denied, enable HandsFree under System Settings → Privacy & Security → Microphone.
2. Click **Open settings** for Accessibility / Input Monitoring and enable HandsFree in **both** Privacy & Security panes. Accessibility is needed to inspect the original text field and post Paste; Input Monitoring is needed for the global Fn event tap. Quit/relaunch after changing grants. The app never changes preferences itself.
3. Click **Download** to explicitly fetch **Whisper base.en (147,964,211 bytes)** from `huggingface.co/ggerganov/whisper.cpp`. SHA-256 is pinned and verified before atomic installation. No model download happens on launch. Subsequent dictation works offline. Retry a failed download; partial files are discarded rather than resumed.
4. In Keyboard settings, set **“Press 🌐 key to” → Do Nothing**. Also disable macOS Dictation's Fn/double-Fn shortcut if enabled. Select a text box in another app and briefly tap Fn (under 450 ms). Fn held down, key repeats, Fn+arrows/F-keys, and modifier chords must not toggle recording. External keyboards that do not expose hardware Fn events are unsupported.

Close settings to keep the app in the menu bar. Left-click its waveform icon for settings / last transcript; right-click for the menu, cancel, or quit. There is no login-item auto-start in v1.

## Dashboard, sounds, and local usage

The main window uses a softer, system-light/dark design: warm neutral surfaces, rounded top navigation with SVG icons, native system type, and the existing lime waveform logo. Overview shows real local usage totals, the saved shortcut, and the last transcript with manual **Copy text**. Setup appears only when something is missing. Settings groups shortcuts, sound, permissions/model, and local privacy controls. The compact native pill and processing animation are unchanged.

**Keyboard shortcut:** keep the default **Fn**, choose **Option + Space** or **Control + Shift + Space**, or focus **Record shortcut** and press your own combination. Custom bindings require Control, Option or Command plus a letter, number or Space; bare typing, pure modifiers, common Command editing/destructive actions, Spotlight, Control-Space, and screenshot shortcuts are rejected by both UI and backend. Escape exits the recorder without changing the binding. Capturing temporarily suspends global triggers and Escape cancellation, then restores them on completion, blur or timeout. Changes save before applying; invalid settings or save failures leave the previous binding intact. A corrupt saved binding falls back to Fn without discarding valid usage totals.

Combinations are observed globally through the existing native CGEvent tap, including when HandsFree is inactive; exact modifiers are required and key repeats/held keys do not retrigger. Choosing a combination disables Fn gestures. Input Monitoring must be granted and the tap connected; missing access is shown in readiness. This is a listen-only hook, **not exclusive shortcut registration**: it cannot detect every other app's shortcuts or swallow keys. The shortcut also reaches the foreground app. Choose a conflict-free combination. Bindings use physical `KeyboardEvent.code` → macOS virtual key positions, labeled using **US key positions** rather than claiming layout-dependent characters. Non-US keyboards may place a different character on that key; some external keyboards do not expose Fn. Secure Input can block global observation.

**Listening sound:** choose **Soft tap** (90 ms warm descending single pulse, default) or **Soft bell** (150 ms single tone with a faint overtone), both original locally synthesized profiles with gentle zero-slope envelopes, not copied audio. Toggle sound off independently, and adjust persisted **Volume** from 0–100%, default **50%**, without changing system volume. Existing sound-enabled and volume preferences are preserved; older settings without a style adopt Soft tap, replacing the previous two-note cue. Selection never autoplays. **Preview sound** is explicit and idle-only, works even when sound is off (0% remains silent), and never opens the microphone. Starting dictation interrupts a preview.

Once the recorder is prepared, the selected cue plays once and capture starts after its actual duration plus a 180 ms quiet tail (270 ms for tap, 330 ms for bell), without blocking the main thread. Cancellation is checked again immediately before capture; stopping invalidates a pending start. Speak after the cue. The tail accommodates common Bluetooth output buffering, but unusually delayed routes/acoustic echo still require hardware testing; disable sounds if needed. There are no stop/cancel sounds. Reduced Motion removes processing pulsing, and the waveform always represents actual metering rather than a fabricated animation.

**Usage tracking starts now; no past usage is inferred.** Each successful, nonempty inference increments dictations and whitespace-delimited words once, regardless of whether automatic Paste is possible. Silence, failed inference, and cancelled sessions do not count. “Recorded” seconds are the accepted WAV duration of successful dictations (including pauses), not voice-activity-only speech time. Estimated time saved is calculated **per dictation** as `max(0, words / 40 * 60 - recording_seconds)` using a disclosed **40 words/minute** typing baseline; inference time is not subtracted. This is an estimate, not a measured productivity gain.

Only aggregate counts/durations/estimates, the shortcut and sound preferences are saved in `~/Library/Application Support/com.handsfree.local/usage.json`. Writes run on backend workers, use an owner-only (`0600`) temporary file, sync, and atomic rename inside the owner-only directory (`0700`). No transcript or audio history is written to this file. Saving is best-effort: failures are visible in the app, and in-memory usage may be lost on quit. Invalid/unreadable saved data produces a visible warning and fresh in-memory defaults; a subsequent successful update replaces it. Missing new preference fields migrate to Fn/Soft tap; an invalid shortcut falls back independently. **Reset totals** requires explicit confirmation and preserves the model, shortcut, sound style, enabled state and volume.

## Behavior and safety

- English-only `whisper-rs` / whisper.cpp inference with **Metal**. Four CPU worker threads; the model is loaded per utterance (a little extra startup latency, no permanent model memory). There is no LLM rewrite, grammar cleanup, filler deletion, or remote fallback.
- **Filler preservation is best-effort, not guaranteed.** A verbatim/disfluency prompt encourages “um”, “uh”, repetitions, etc., but Whisper can omit them, add punctuation, or hallucinate. v1 is not a lossless verbatim engine. Confirm accuracy before using consequential text.
- Uses the macOS default microphone, requesting 16 kHz mono signed-16-bit WAV. The pill responds to microphone power, not a simulated waveform. Quiet/short recordings and high no-speech-probability segments are rejected. Very soft speech may be treated as silence. At two minutes recording stops and transcribes automatically.
- One active recording/inference/download at a time; single-instance plugin prevents simultaneous processes sharing audio files. Cancel immediately invalidates a lock-free epoch on receipt, independent of the FIFO worker and state mutex. Fn taps retain their Fn-down epoch, so queued or held taps cannot re-arm a cancelled session. Native main-thread callbacks recheck the epoch before starting capture, publishing clipboard text, and submitting Paste; cancelled results do not commit transcript or usage totals. If the app still owns a cancelled clipboard publication, it restores the previous clipboard. Cancellation after the final event-submission/acceptance boundary cannot undo an already submitted Paste. During inference, Cancel keeps the engine busy until computation returns (no unsafe forced context destruction).
- Stores the original frontmost app PID and focused Accessibility element across stop/transcription. Immediately before Paste, **both must still match**. Supports non-secure text fields, text areas, combo boxes, and custom editors that explicitly expose writable AX selected text; disabled/read-only and secure fields (including secure ancestors) are rejected both at start and finish. AX elements recreated by an app are intentionally not matched by labels, coordinates, or identifiers. Focus mismatch and missing AX support keep the transcript in settings. Paste events are addressed to the original PID; the app never activates it or sends Enter/Return. AX inspection and event delivery are not atomic; avoid switching focus at the exact instant transcription finishes.
- If automatic insertion is refused (including forgetting to click a textbox, missing AX focus, changed app/element, secure/unsupported/read-only fields), a successful nonempty transcript is **automatically copied**, with **Copied** on the dashboard and a brief friendly native capsule. The dashboard retains the exact `[start:reason]` or `[finish:reason]` diagnostic without reading textbox contents. Secure fields still never receive Paste; the intended dictation may be copied. Copy failure keeps the transcript on Overview for manual **Copy text**. Silence, failed inference and cancellation do not copy. Even a successful event submission is labeled **insertion not confirmed**: macOS does not acknowledge acceptance, so a submitted Paste is never followed by automatic copy or blind retry.
- Inserts a single line: control characters (including newlines / Return, tabs, NUL, and Escape) become spaces. Words, punctuation, repetitions, and fillers are not rewritten. There is no simulated Enter key.
- Successful Paste submission temporarily uses the system clipboard, then restores its previous contents after one second (or normal quit) **only if the clipboard has not changed**. **Automatic fallback copy intentionally overwrites your clipboard and leaves the transcript there** until you replace it; manual Copy does the same. Earlier paste timers and normal quit never restore an old snapshot over an explicit copy. Clipboard managers / Universal Clipboard can observe and retain dictation, including fallback from a secure field. A crash during temporary Paste can also leave the transcript on the clipboard. Slow apps can miss Paste; synthetic event delivery is not an insertion acknowledgement. The app retains the last result in memory for manual Copy even when Paste is attempted. Clipboard ownership is not a privacy boundary.
- Audio lives in `~/Library/Application Support/com.handsfree.local/recording.wav` inside an owner-only directory, and is deleted after success, failure, cancel, normal quit, and on next launch after a crash. Sudden process/OS failure can leave the WAV until next launch. The model lives in the same directory as `ggml-base.en.bin`. Transcripts are kept **only in process memory**, not a history database. No telemetry, analytics, or transcript uploads.
- Escape is observed, **not swallowed**, so it also reaches the foreground app. Fn is observed, not remapped. macOS Secure Input, lock screens, permission revocation, device disconnects, sandboxed/custom editors, full-screen Spaces, and clipboard consumers require manual testing. No automatic retry into another field.

## Verification

```sh
npm test                         # frontend state + pure Swift paste policy (macOS)
npm run build                    # strict TypeScript + production Vite build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run tauri build -- --bundles app
codesign --verify --deep --strict src-tauri/target/release/bundle/macos/HandsFree.app
```

Optional headless UI smoke check (uses explicit test fixtures, never real recording): start `npm run dev -- --port 5187`, then run `BROWSER_BINARY='/path/to/Chromium-or-Brave' node tests/ui-smoke.mjs`. It checks navigation, shortcut presets/recording/validation/save failures, sound style selection without autoplay, toggle/volume/idle-only preview, reset confirmation/cancellation, transcript escaping, copy, and controls at 400/560/740/980 px in light and dark modes. It does not take screenshots or request native permissions. Stop the dev server afterward.

Rust unit tests cover Fn tap/hold/repeat/chord filtering, explicit finish after cancellation/stale timeout, receipt-time cancellation with a held state mutex, queued/held taps across cancellation, delivery/result rejection, silence/short/click rejection, friendly no-speech messages, paste diagnostics, shortcut validation/labels/migration, usage calculations, private atomic storage, settings persistence, corrupt data, and reset. Frontend tests cover readiness, duration formatting and shortcut recorder validation. Swift tests cover exact native key/modifier matching with repeat/held filtering, field-policy/ABI codes, the actual queued-main native paste closure with a revoked callback token, and the 150 × 44 pt capsule's flipped-coordinate checkmark, 34 pt button hit targets (28 pt visible circles), state drawing/centering/nonactivation, both cue profiles’ duration/headroom/smooth endpoints, preview guards, and cancellation gate, without capture, playback, or permission prompts. Hardware shortcut delivery with HandsFree inactive, permission prompts, actual capture, sound-device timing, overlay button interaction without focus changes, Metal inference with downloaded weights, AX identity behavior in individual apps, paste correctness, Spaces placement, and filler accuracy require user-authorized interactive testing; compilation alone does not prove them.

### Manual acceptance checklist

In TextEdit, browser text areas, and your usual editor: verify start/stop without focus change, meter response, processing state, exactly one paste, no Enter, and clipboard restoration. Try “Um, I, I think, uh, you know, this works” and inspect filler retention. Test silence, Escape while recording/inference, rapid Fn taps, Fn+arrow, Fn held >450 ms, changing focus before completion, password fields, a disconnected microphone, denied permissions, and offline operation after model setup. Verify no paste after cancellation or focus mismatch.

For fallback acceptance, start with no textbox selected, then try changing app/field and unsupported/read-only/password targets: expect no Paste, **Copied**, the insertion-safe transcript remaining on the clipboard beyond one second and after quit, and one usage increment. Paste manually into a safe field to verify contents. Verify a submitted Paste still restores the old clipboard without fallback copy, and silence/failure/cancellation leave clipboard and totals unchanged. These interactive cases require user-authorized recording; the automated native harness instead uses an isolated pasteboard and revoked-token calls without permissions or audio.

## Layout

- `src/`: small TypeScript/Vite settings + onboarding; no microphone/browser speech API.
- `src-tauri/src/main.rs`: model lifecycle, verified explicit download, state/concurrency, WAV validation, local inference, tray, IPC.
- `src-tauri/src/logic.rs`: independently testable hotkey/silence logic.
- `src-tauri/src/storage.rs`: aggregate usage, sound preference, and private atomic persistence.
- `src-tauri/native/Bridge.swift`: global CGEvent tap, AVAudioRecorder, AX target validation, clipboard paste, AppKit pill. Compiled to a static library by `build.rs`.
- `src-tauri/Info.plist`: microphone usage description and menu-bar (`LSUIElement`) application identity.

Upstream: [Tauri](https://v2.tauri.app/), [whisper-rs](https://github.com/tazz4843/whisper-rs), [whisper.cpp / model source](https://huggingface.co/ggerganov/whisper.cpp). See [release licensing and the publication gate](RELEASING.md#license-inventory) before redistribution.
