# HandsFree v0.1.1-beta.22

Unpublished experimental Mac beta candidate · Apple Silicon · macOS 14+

Internal app version: **0.1.1**. Public downloads and the signed update feed
remain on **v0.1.1-beta.21**. Candidate coordinates are disabled; this document
is not a publication, installation or acceptance receipt.

## Capture-first contract

- Remove the listening/start cue and its acoustic tail. Capture proceeds after
  native validation without waiting for startup sound playback. Keep completion
  sound only, with output construction, decode and preparation deferred until
  capture has closed and drained; no idle microphone or always-on capture.
- Preserve owner/FIFO/generation/epoch boundaries, cancellation, deadlines,
  bounded startup and stale-session rejection. Completion playback rechecks
  authorization after blocking output validation (`SessionCueOutput.playIfAllowed`)
  so cancellation or expiry during validation cannot authorize a late play.
- This removes the avoidable roughly 400 ms start-cue/tail cost plus output
  preparation from the capture path. It does **not** promise instant cold
  Bluetooth startup: route preparation remains hardware-dependent.

## Compact controls and metadata

- Keep the red shortcut inside its existing box; remove the Practice Settings
  shortcut. Use compact 32 px utility icons, borderless selects, and an inline
  health micro-row with an icon refresh action.
- Contain native WebKit select overflow. Refresh microphone/default-device
  metadata on explicit view, focus, settings and status actions, rather than
  displaying a stale default-device label. Metadata refresh does not authorize
  native microphone capture.

## Evidence and limits at candidate preparation

Final local verification passed **324 Node tests / 1 skipped**, **90 Rust tests /
3 ignored**, frontend build, Rust formatting, strict Clippy and the full browser
suite. This includes 48 real offscreen WebKit layout cases with measured scrollbar
gutters and a reversible negative control for the original inner overflow.
Independent review found one completion authorization race after blocking output
validation; the primary repaired it and added cancellation/expiry tests at that
boundary. Subsequent native/UI review found no substantive issues. Browser checks
cover compact controls, aligned microphone/refresh row, red custom shortcuts,
Sidebar Settings privacy teardown, direct recovery and unchanged inline updates.
Trusted keyboard events reach the native select; actual macOS popup choice is
not driven by the headless harness and is not claimed as acceptance.

One user-approved instrumented attempt was **BLOCKED** by a permission timeout
with zero capture admissions; it is not a pass and supplies no new hardware
latency evidence. The installed beta 21 baseline measured 1293 ms route
preparation, a 220 ms cue and 180 ms tail, with actual first PCM at 1767 ms.
Those are beta 21 observations, not beta 22 measurements.
