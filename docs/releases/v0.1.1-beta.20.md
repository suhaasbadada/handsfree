## Narrow capture startup hotfix

The owner reported beta 19 Fn capture stuck at **Starting**, then an error.
Current diagnostics showed permission, model and shortcut hook ready, with
`failureDomain: Microphone changed during capture startup`, `input_prepare`
and `negotiationAttempts: 1`. This was not a missing-setup diagnosis.

Initial configuration events during tap installation, engine start and precommit
inspection are now recognized through the locked startup commit, rather than
only during prepare. A valid initial configuration change can use the existing
bounded two-attempt reconciliation contract: same device UID, epoch and start
gate, permanent cancellation, independent cleanup, disabled PCM until commit and
the single three-second startup watchdog. That contract is not expanded.
Generic errors, Objective-C exceptions, cancellation and runtime errors do not
authorize retry. No global hardware-rate writes, device-name special cases,
silent device changes or additional UI changes are introduced. The beta 19 UI,
cue assets, volume defaults, privacy and usage semantics remain unchanged.
