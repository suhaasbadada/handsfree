## Optional Compatibility paste

After this release is published, quit HandsFree, run `brew update` and
`brew upgrade --cask suhaasbadada/handsfree/handsfree`, or replace the Applications
copy using the versioned DMG. Then open **Settings → Compatibility paste** and
enable the switch yourself. **Default off**, including upgrades and older settings.
Updating does not enable it automatically.

This Mac-only option can help apps that hide their Accessibility text field
(including the observed beta 4 `AX no_value` manual-paste case). It is not a
guarantee of insertion in every app. When standard delivery has **not attempted**
a paste, compatibility mode can send **one** paste to the verified original app
and window. The exact text field cannot be verified: this intentional, explicit
opt-in is weaker than standard field-level proof. Missing window proof or focus
monitoring leaves text on the clipboard for manual paste. Known secure/read-only
fields and changed targets remain blocked. No Enter/Return is sent.

A native paste attempt is not an acknowledgement that text appeared. Once an
attempt has been made, no compatibility retry is sent, preventing duplicate paste.
Check the result before manually pasting. Clipboard fallback replaces clipboard
contents. No Accessibility settings are forcibly written and no permission reset
or new signing identity is required.

Toggle remains the default; existing optional Push to talk, Fn/custom shortcuts,
Clean/Warm sounds, volume, model files, recording limits, settings and aggregate
statistics are preserved. The compatibility switch is hidden on Windows; the
published Windows beta 3 installer and manifest are unchanged.

**Self-signed, not Developer ID signed or notarized.** The existing local signing
identity is preserved. Follow [installation guidance](../INSTALL.md) and managed
security policy. Notices and corresponding dependency source accompany the DMG;
verify `SHA256SUMS` after publication. No recordings, models, settings or private
signing material are distributed.

Automated policy/native fixtures and compiled-artifact checks are not live editor
insertion, microphone, global-hook timing, clean/separate-Mac or Windows hardware
acceptance. Those manual checks remain pending; no live insertion is claimed.
