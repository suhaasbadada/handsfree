## Configuration-notification repair

The reproduced failure was an accepted-input configuration notification before
first PCM: the old policy treated the notification itself as fatal, even when
the actual hardware route was still valid. A notification is now a request for
read-only certification, not proof of hardware failure or permission to retry.
The serial native owner checks actual input identity/device UID against the
bound device, hardware/output/tap formats and engine running state. Certificates
are revision-bound; a notification racing validation invalidates its result.

PCM remains provisional: invalid certification fails the whole capture rather
than allowing a partial transcript. Final drain certification is mandatory before
EOS/success. Independent review by Joffrey found a missing final-hook fail-open;
the primary added a fail-closed guard and regression coverage. Missing hooks must
not silently certify a recording.

Preserve owner/FIFO/epoch/generation boundaries, cancellation, stale-session
rejection and the 3s watchdog. There is no added wait, retry, idle microphone,
hardware setting change or silent device switch. Capture-first startup and
completion-only sound after capture close/drain remain unchanged. This does not
promise instant cold Bluetooth startup.
